# แผนฝึกภาษาอังกฤษสำหรับงาน + เขียนโค้ดสำหรับงาน (2026-11-26 — เจ้าของตกลงแล้ว)

ภาคต่อของ `docs/engineering-plan.md` · ROADMAP แถว 55–61 · ใช้กฎเดิมทั้งหมดใน CLAUDE.md (สูตรอยู่ในไฟล์ `*-calc.js`, ไทย/อังกฤษ, ห้ามมีข้อความอธิบาย, bump `CACHE`, `credits.html`)

## เหตุผล (สรุปแบบไม่ระบุตัวตน — repo เป็น public)

- **ภาษาอังกฤษ**: อ่านเอกสารเทคนิคได้ แต่มีปัญหา 2 ข้อ คือ (1) สะกดผิดเรื่องสระ เช่น ea/ee, a/e, e ท้ายคำที่ไม่ออกเสียง, -tion/-sion และ (2) พูดแล้วนึกคำไม่ออก ซึ่งเป็นปัญหาการดึงคำมาใช้ ไม่ใช่ไม่รู้คำ ยังไม่เคยคุยกับชาวต่างชาติ · เป้าหมายคือ**ใช้ทำงานได้** (ประชุม อีเมล รายงาน สัญญา) ไม่ใช่คะแนนสอบ
- **โค้ด**: ต้องการใช้ทำเอกสาร นำเสนองาน เก็บข้อมูล และตรวจเอกสาร · ลำดับความคุ้มคือ Python > SQL > HTML/JS · **ไม่ทำแทร็ก Java** เพราะไม่ช่วยงานแบบนี้
- **เวลา**: เจ้าของกำลังสอบกฎหมาย หน้าเว็บจึงต้องรองรับการฝึกสั้นๆ วันละ 10–20 นาที ไม่บังคับให้นั่งนาน

## ภาษาอังกฤษ

> **ส่งต่อให้ session ภาษา (2026-11-26)**: มี session อื่นพัฒนาหน้า languages อยู่ (branch `claude/lang-l0-data`, `lang-l1-packs`, `lang-l4-subs`, `lang-l5-roleplay`; แผน `docs/languages-design.md` L0–L9; ROADMAP แถว 21–32 ใน branch นั้น) EW1–EW4 ด้านล่างจึงเป็น**ความต้องการจากเจ้าของ**ให้ session นั้นนำไปรวมกับแผนของตัวเอง ไม่ใช่งานแยกที่ session อื่นทำเอง (แก้ `languages.jsx` พร้อมกันจะชนกันทั้ง `.compiled.js` และ `react-pages.css`)
> - EW3 (ฝึกพูดโต้ตอบ) **ทับกับ L5 สวมบทบาท 8 ฉาก ที่ทำแล้ว** → สิ่งที่ยังขาดคือฉากงาน (ประชุมหน้างาน แจ้งเหตุขัดข้อง ผู้รับเหมา ความปลอดภัย อีเมล ประเมินราคา สัญญา นำเสนอลูกค้า ขาย/presales และสัมภาษณ์งานตำแหน่งวิศวกร — L5 มีฉากสัมภาษณ์งานทั่วไปอยู่แล้ว) และการแสดงประโยคของผู้ใช้ฉบับแก้คู่กัน ถ้า L5 ยังไม่มี
> - EW1 (ประโยคงาน) อาจไปอยู่ใน `lang-data` หรือ lang-packs ของ L0/L1 แล้วแต่ session ภาษาตัดสิน
> - EW2 (สมุดคำสะกดผิด) และ EW4 (พูดสรุปงานวันนี้) ยังไม่มีในแผน L0–L9 ณ วันที่ตรวจ
> - เลขแถวของแผนนี้เลื่อนเป็น 40–61 เพื่อไม่ชนกับแถว 21–32 ของ session ภาษา

### EW1 · ชุดประโยคสำหรับงาน (ROADMAP แถว 55)

- เพิ่มหมวดใน `lang-data` ของ `lang-en` (โครงเดิม: หมวด → ประโยค) แบ่ง 10 หมวด คือ ประชุมหน้างาน · แจ้งเหตุขัดข้องและสถานะงานซ่อม · คุยกับผู้รับเหมา/ตรวจรับงาน · ความปลอดภัย (Permit to Work, LOTO) · อีเมลและรายงาน · ประเมินราคาและใบเสนอราคา · เงื่อนไขสัญญา (variation, extension of time, liquidated damages, defects liability) · นำเสนองานลูกค้า/ผู้บริหาร · ขายและเจรจากับลูกค้า (presales) · สัมภาษณ์งาน (แนะนำตัว เล่าผลงานแบบ STAR ตอบคำถามเทคนิค) — สองหมวดหลังเจ้าของเพิ่ม 2026-11-26
- หมวดละ 20–30 ประโยค เป็นประโยคที่ใช้ได้ทันที ("We expect a two-day delay because the spare parts haven't arrived.") มีคำแปลไทยและหมายเหตุสั้นเฉพาะเมื่อจำเป็น
- เข้าโหมดที่มีอยู่ทั้งหมดได้เลย (ฟังแล้วเขียน, พูดตาม, คิวทบทวน) ไม่ต้องเขียนโหมดใหม่
- **ห้ามแก้หรือสลับประโยคเดิม** เพราะคีย์ SRS ผูกกับประโยค · เพิ่มเป็นหมวดใหม่เท่านั้น · `./build-react.sh` ถ้าแก้ `.html` (CSS ของ Tailwind อาจเปลี่ยน)
- ประโยคต้องเป็นภาษาอังกฤษที่ถูกและเป็นธรรมชาติ (ใช้ `humanizer`) · ข้อความสัญญาเขียนเอง **ไม่คัดลอกข้อความ FIDIC** (มีลิขสิทธิ์)

**โมเดล** Opus 5.5 · **effort** medium · **skill** `humanizer`

### EW2 · สมุดคำที่สะกดผิด (ROADMAP แถว 56)

- ตรรกะล้วนในไฟล์ใหม่ `spell-calc.js` (UMD, ไม่มี DOM): `diffKind(target, typed)` จำแนกความผิดเป็นรูปแบบ ได้แก่ `vowel-pair` (ea↔ee, ie↔ei, ou↔ow), `vowel-swap` (a↔e, i↔y), `silent-e`, `double` (ตัวซ้ำขาด/เกิน), `suffix` (-tion/-sion, -able/-ible, -ance/-ence), `other` · known-answer ≥ 40 กรณีใน spec
- โหมดฟังแล้วเขียนและแต่งประโยค: เมื่อสะกดผิด บันทึก `{word, kind, count, last}` ลง**คีย์ใหม่** `lang-practice:spell` (sync map — 1 คำ = 1 doc ให้หลายเครื่องไม่ทับกัน) ข้าง `lang-practice:wrong` เดิม (ไม่แก้รูปแบบคีย์เดิม) · กฎใน `data-registry.js` ต้องอยู่เหนือ `{prefix:'lang-practice:'}`
- หน้าแสดงคำที่ผิดบ่อยจัดกลุ่มตามรูปแบบ และปุ่ม "ฝึกกลุ่มนี้" ที่เข้าโหมดฟังแล้วเขียนเฉพาะคำในกลุ่ม
- `tests/` spec ใหม่ (หรือขยาย `languages-ai.spec.js`) + `lang-round`/`edu-audit` ตามที่ครอบคลุมหน้านี้

**โมเดล** Sonnet 5.5 · **effort** high · **skill** `test-driven-development`, `tanot-design`, `vercel-react-best-practices`

### EW3 · ฝึกพูดโต้ตอบกับ AI (ROADMAP แถว 57)

- โหมดใหม่ในอังกฤษ "ฝึกพูดตามสถานการณ์": เลือกสถานการณ์ (ใช้ 8 หมวดของ EW1) → AI เป็นอีกฝ่าย (ที่ปรึกษา ผู้รับเหมาต่างชาติ หัวหน้า) พูดประโยคสั้น → ผู้ใช้กดพูด → ถอดเสียง (คลาวด์ `AiClient.asr` บน pages.dev ไม่งั้นใช้ `asr-worker.js` ที่หน้ามีอยู่) → AI ตอบต่อ **พร้อม**แสดงประโยคของผู้ใช้ฉบับที่แก้แล้วคู่กัน → กดเก็บประโยคที่แก้เข้าการ์ดทบทวนได้
- AI เสียงพูดใช้ TTS อังกฤษที่เว็บมีอยู่ (`Xenova/mms-tts-eng` ผ่านทางเดียวกับวิดเจ็ต) หรือ `speechSynthesis` บน iOS
- ข้อความสั่ง AI (prompt) อยู่ในไฟล์ calc ใหม่ (`speak-calc.js`: `messages(scenario, history)` / `parseReply` ที่ทนผลลัพธ์ผิดรูป) · ใช้ `/api/ai/chat` โมเดล `main` เท่านั้น (ฟรี) ห้ามเรียก `/api/ocr`/Claude
- ไม่มีคลาวด์และเป็น iOS = ซ่อนโหมดนี้ · บทสนทนาไม่เก็บ เก็บเฉพาะประโยคที่ผู้ใช้กดเก็บ (ใช้คีย์ SRS เดิมของหน้า)

**โมเดล** Opus 5.5 · **effort** high · **skill** `tanot-design`, `vercel-react-best-practices`, `transformers-js` (ถ้าแตะ TTS), `test-driven-development`

### EW4 · พูดสรุปงานวันนี้ (ROADMAP แถว 58)

- พูดเล่างานของวันเป็นภาษาอังกฤษไม่เกิน 2 นาที → ถอดเสียง → AI แก้ไวยากรณ์และเสนอคำที่เหมาะกว่า → แสดงต้นฉบับกับฉบับแก้คู่กัน → เลือกประโยคเก็บเข้าการ์ด
- ใช้ส่วนประกอบเดียวกับ EW3 / L5 ของ session ภาษา · **ไม่เก็บเสียงและข้อความถอดเสียง** (เหมือน `lecture`) เก็บเฉพาะประโยคที่เลือก · นับเป็นกิจกรรมรายวันผ่าน `LearnCore.award` แหล่งเดิมของ languages

**โมเดล** Sonnet 5.5 · **effort** high · **skill** `tanot-design`, `vercel-react-best-practices`

## เขียนโค้ด

### C1 · แทร็ก Python พื้นฐานใน `coding.html` (ROADMAP แถว 59)

- kind ใหม่ `py`: รันใน **Worker** (`py-runner-worker.js`) ที่โหลด Pyodide รุ่นเดียวกับ `run.html` (0.26.4) มี timeout + `terminate()` ฆ่าลูปไม่รู้จบได้ (ตามเหตุผลที่หัว `coding.js` เขียนไว้) · โหลดตอนเปิดแทร็ก Python ครั้งแรกเท่านั้น และแสดง MB ระหว่างโหลด (Pyodide หลาย MB)
- ตรวจคำตอบแบบเดียวกับแทร็ก JS (`log-includes` ฯลฯ) + ชนิดใหม่ `py-eval` (เรียกฟังก์ชันของผู้เรียนด้วยค่าทดสอบ)
- บทเรียน 6 แทร็ก: ตัวแปร/ชนิดข้อมูล · เงื่อนไข/ลูป · ฟังก์ชัน · list/dict · สตริงและการจัดรูปแบบตัวเลข · ไฟล์และ CSV (ไฟล์จำลองใน FS ของ Pyodide)
- **เพิ่มการ์ด Pyodide ใน `credits.html`** (MPL-2.0) ซึ่งเป็นช่องว่างเดิมของ `run.html` ด้วย · ถ้าย้ายไปใช้ vendor ต้องเป็นงานแยก (ไฟล์ใหญ่)
- `PROGRESS_KEY` เดิมใช้ต่อ (id แทร็กใหม่ไม่ชนของเดิม) · `hobby-audit.spec.js` (coding) เพิ่ม state แทร็ก Python (Pyodide หลอกในเทสต์ — CI ไม่โหลดของจริง)

**โมเดล** Opus 5.5 · **effort** high · **skill** `security-and-hardening` (รันโค้ดผู้ใช้), `test-driven-development`, `tanot-design`

### C2 · แทร็ก Python สำหรับงาน (ROADMAP แถว 60)

- โจทย์ใช้ข้อมูลสมมุติที่เหมือนงานจริง (ไม่ใช้ข้อมูลจริงของหน่วยงาน): รวมไฟล์บันทึก PM หลายเดือน · หา MTBF/MTTR จากรายการเหตุขัดข้อง · รวมชั่วโมงคนตามช่างและงาน · ทำตาราง BOQ แล้วรวมราคา · เทียบรายการในใบเสนอราคา 2 ฉบับ · ทำกราฟแนวโน้ม · สร้างรายงานจากแม่แบบ
- ไลบรารี: pandas, matplotlib (มีใน Pyodide) · openpyxl, python-docx (ติดตั้งผ่าน `micropip` ใน Pyodide ต้องตรวจว่าใช้ได้จริงก่อนออกแบบโจทย์ ถ้าใช้ไม่ได้ให้ใช้ CSV แทน และเขียนไว้ในแถว)
- คำตอบที่เป็นตัวเลข (MTBF, ผลรวม) ต้องตรงกับฟังก์ชันของเว็บที่มีอยู่ (`MntCalc` ฯลฯ) ตรวจในเทสต์
- ผลที่เป็นไฟล์ (xlsx/docx/png) ให้ผู้เรียนดาวน์โหลดได้ ไม่เก็บลงเครื่อง

**โมเดล** Opus 5.5 · **effort** high · **skill** `test-driven-development`, `humanizer` (คำอธิบายโจทย์)

### C3 · แทร็ก SQL (ROADMAP แถว 61)

- kind ใหม่ `sql`: ใช้ sql.js (SQLite wasm, MIT) **vendor ล็อกรุ่น** ใน `vendor/sql.js/` รันใน Worker · ฐานข้อมูลจำลองงานซ่อมบำรุง (สินทรัพย์ ใบสั่งงาน ช่าง อะไหล่) สร้างจากสคริปต์ในเทสต์/ไฟล์ `.sql` ที่ commit
- บทเรียน: SELECT/WHERE · ORDER/LIMIT · GROUP BY/สรุปผล · JOIN · วันที่ · โจทย์รวม (งานค้างเกิน 30 วัน, ค่าอะไหล่ต่อสินทรัพย์)
- ตรวจคำตอบด้วยการเทียบผลลัพธ์ของคำสั่งผู้เรียนกับคำสั่งเฉลย (ลำดับแถวนับเฉพาะโจทย์ที่มี ORDER BY)
- การ์ด sql.js ใน `credits.html` · `sw.js` แคช wasm ตอนใช้ครั้งแรก (ไม่อยู่ใน PRECACHE เหมือน vendor หนักตัวอื่น)

**โมเดล** Sonnet 5.5 · **effort** high · **skill** `test-driven-development`, `tanot-design`
