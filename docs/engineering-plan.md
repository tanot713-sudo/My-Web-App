# แผนพัฒนากลุ่มวิศวกรรม (ปรับ 2026-11-26 — เจ้าของเลือกสายงานแล้ว)

## เป้าหมาย (เจ้าของบอก 2026-11-26)

ส่วนวิศวกรรมของเว็บต้อง **ใช้ทำงานได้จริงและทำให้เข้าใจจริง** หลายคนจบมาแล้วไม่ได้ทำงานตรงสาย จึงต้องเรียนงานที่ทำอยู่จริงได้จากที่นี่ ไม่ใช่แค่ท่องทฤษฎีของสาขาที่จบมา

ทิศทางจึงเปลี่ยนจากแผนรอบแรก (และเจ้าของย้ำว่าทฤษฎีคือพื้นฐาน — ดูหัวข้อ T):
- **จาก "สาขา" เป็น "สายงาน"**: เรียนตามตำแหน่งงานที่ทำจริง เช่น ช่างหรือวิศวกรบำรุงรักษา วิศวกรหน้างาน หรือคนประเมินราคา ไม่ใช่ตามภาควิชา
- **จาก "จำคำตอบ" เป็น "ตัดสินใจในสถานการณ์"**: ข้อสอบเป็นสถานการณ์หน้างาน และตอบแล้วต้องเห็นเหตุผลทุกข้อ (ตอนนี้ระบบมีแค่ถูกหรือผิด)
- **บทเรียนต่อกับเครื่องมือ**: โจทย์ที่ต้องคำนวณต้องเปิดเครื่องมือในเว็บพร้อมตัวเลขของโจทย์ได้ทันที ใช้ทั้งตอนเรียนและตอนทำงานจริง
- **เครื่องมือต้องเชื่อได้**: ถ้าจะใช้ตัวเลขทำงานจริง สูตรต้องมีตัวเทียบอิสระ (E1) งานนี้จึงยังอยู่ในลำดับต้น

```

   ──> T วิชาพื้นฐานที่สายถัดไปต้องใช้ ──> W2 สายงาน 9 สาย (ทีละสาย: plan → docs → site → contract → rail → solar → network → iso → factory)
                                     ├──> W3 เชื่อมสาย contract กับห้องเรียนกฎหมาย
                                     └──> W4 เปิดเครื่องคำนวณพร้อมตัวเลข (electrical → run → maintenance)
E1 ค่าอ้างอิง pandapower ──> E2 รีเลย์/TCC        E4 แนวโน้มค่าวัด maintenance        E8 แท็บ Solar PV
W5 คำศัพท์หน้างาน · W6 แนะแนวสาขา (13 สาขาเดิม)   E3 DGA · E6 DXF ทดสอบ · E7 พักไว้
```

1. **W1 + W4** เป็นโครงที่ทุกอย่างใช้ร่วมกัน งานเล็กแต่ต้องทำก่อน
2. **T (`f-units`, `f-reliability`, `f-econ`) แล้วตามด้วย W2 สาย `plan`** สลับกันแบบนี้ทุกสาย ทฤษฎีมาก่อนงานเสมอ · เพราะตรงกับงาน planner/ประเมินราคาที่เจ้าของทำ และต่อกับ `run` + `maintenance` ได้ทันที · เจ้าของลองใช้แล้วปรับรูปแบบก่อนทำสายถัดไป
3. **E1 → E2 / E4 / E8** เครื่องมือทำงาน ทำสลับกับการเขียนเนื้อหาได้ (คนละไฟล์กัน) · E8 ขึ้นมาเพราะเจ้าของดูงาน solar อยู่ตอนนี้
4. ที่เหลือทำตามที่เจ้าของเลือก

## T · ทฤษฎีพื้นฐาน (ROADMAP แถว 54 — เจ้าของเพิ่ม 2026-11-26)

เจ้าของชี้ว่า **ทฤษฎีคือพื้นฐาน ถ้าไม่มีก็ไปต่อไม่ได้** สายงาน (W2) จึงไม่ได้มาแทนทฤษฎี แต่ต้องตั้งอยู่บนทฤษฎี ปัญหาของหมวด 13 สาขาเดิมคือบางเกินไปจนใช้เป็นฐานไม่ได้ (ภาพรวมกับข้อสอบ 4 ข้อ) ไม่ใช่เพราะเป็นทฤษฎี

**หลักการ**
- **ทฤษฎีเป็นหมวดของตัวเอง** `foundation` ในห้องเรียนวิศวกรรม เรียนเป็นวิชาได้ครบโดยไม่ต้องผ่านสายงาน
- **ต่อกันทั้งสองทาง**: หัวข้อในสายงานมีฟิลด์ `pre: ['<id ทฤษฎี>', …]` แสดงเป็น "ต้องรู้ก่อน" พร้อมลิงก์ · หัวข้อทฤษฎีมีฟิลด์ `usedIn` ซึ่ง**สร้างอัตโนมัติจาก `pre`** ไม่ต้องเขียนเอง (กันสองฝั่งไม่ตรงกัน) แสดงเป็น "ใช้ในงาน"
- **ลึกพอใช้คำนวณได้จริง**: แต่ละหัวข้อมีบทเรียน (นิยาม → สมการพร้อมหน่วย → ที่มาของสมการแบบย่อ → ตัวอย่างคำนวณ 2–3 ตัวอย่าง → ข้อจำกัดของสมการ) และข้อสอบ 8–12 ข้อ แบ่งเป็นข้อแนวคิดกับข้อคำนวณ ทุกข้อมี `why`
- **ตัวอย่างคำนวณตรงกับเครื่องมือ**: สูตรที่เว็บมีฟังก์ชันอยู่แล้ว (`ElecCalc`, `MntCalc` ฯลฯ — NPV/IRR ยังไม่มีฟังก์ชัน ถ้าจะใช้ในเครื่องมือด้วยให้เพิ่มใน calc ไฟล์ใหม่พร้อม known-answer) ต้องใช้ฟังก์ชันนั้นตรวจในเทสต์ · สูตรที่ยังไม่มีให้เขียนค่าคำตอบที่คำนวณด้วยมือพร้อมขั้นตอนในคำอธิบาย PR ให้เจ้าของตรวจ
- **เขียนสมการ**: Markdown ของบทเรียนรองรับแค่ข้อความ `mdToHtml` ใน `classroom-engineering.jsx` (บรรทัด ~295) รองรับแค่ code/ตัวหนา/ตัวเอียง/ไฮไลต์/รายการ จึง ให้เขียนสมการในบรรทัด `code` ด้วยข้อความธรรมดาที่อ่านง่าย (`V = I × R`, ตัวห้อยเป็น Unicode) **ห้ามเพิ่มไลบรารีสมการจาก CDN** ถ้าจำเป็นต้องใช้ KaTeX ต้อง vendor ล็อกรุ่น และเพิ่มแถวแยก

**วิชาพื้นฐาน** (id ตั้งแล้วห้ามเปลี่ยน · เรียงตามที่สาย `plan` ต้องใช้ก่อน)

| id | วิชา | เนื้อหาหลัก | ใช้ในสายงาน |
|---|---|---|---|
| `f-units` | หน่วยและการประมาณค่า | SI, แปลงหน่วย, เลขนัยสำคัญ, ประมาณค่าแบบเร็วก่อนคำนวณละเอียด | ทุกสาย |
| `f-reliability` | สถิติและความน่าเชื่อถือ | ค่าเฉลี่ย/ส่วนเบี่ยงเบน, การแจกแจง exponential/Weibull, MTBF/MTTR/availability, bathtub curve, ระบบอนุกรม/ขนาน | plan, rail (RAMS), factory |
| `f-econ` | เศรษฐศาสตร์วิศวกรรม | มูลค่าเงินตามเวลา, NPV/IRR/payback, ค่าใช้จ่ายตลอดอายุ (LCC), จุดคุ้มทุนซ่อมหรือเปลี่ยน | plan, solar, contract |
| `f-measure` | การวัดและเครื่องมือวัด | ความแม่น/ความละเอียด, ความไม่แน่นอน, สอบเทียบ, มัลติมิเตอร์/แคลมป์/เมกเกอร์/กล้องความร้อน | docs, site, iso |
| `f-circuits` | วงจรไฟฟ้า | DC/AC, phasor, กำลัง P/Q/S และ PF, 3 เฟส, ความต้านทานกับอุณหภูมิ | site, solar, `elec-maint` |
| `f-power` | ระบบไฟฟ้ากำลังและเครื่องจักรไฟฟ้า | หม้อแปลง, มอเตอร์เหนี่ยวนำ, per-unit, ลัดวงจร, การป้องกัน | site, rail, `elec-maint` |
| `f-statics` | กลศาสตร์และกำลังวัสดุ | สมดุลแรง, คาน (แรงเฉือน/โมเมนต์), ความเค้น-ความเครียด, ความล้า | site, rail (ทาง/โครงสร้าง) |
| `f-fluids` | กลศาสตร์ของไหลและเครื่องสูบ | ความดัน, สมการ Bernoulli, การสูญเสียในท่อ, กราฟปั๊ม, cavitation | site (MEP), factory |
| `f-thermo` | อุณหพลศาสตร์และการถ่ายเทความร้อน | กฎข้อ 1–2, การนำ/พา/แผ่รังสีความร้อน, HVAC/ทำความเย็นพื้นฐาน | site (MEP), solar (อุณหภูมิแผง), factory |
| `f-materials` | วัสดุวิศวกรรมและการกัดกร่อน | โลหะ/พอลิเมอร์, การเลือกวัสดุ, กลไกการกัดกร่อนและการป้องกัน | site, rail, factory |
| `f-control` | ระบบควบคุมและ PLC | ป้อนกลับ, PID, เซนเซอร์/แอคชูเอเตอร์, ladder logic พื้นฐาน | factory, network (SCADA) |
| `f-drawing` | เขียนแบบและอ่านแบบ | ภาพฉาย, มิติและพิกัดความเผื่อ (GD&T พื้นฐาน), สัญลักษณ์แบบไฟฟ้า/เครื่องกล/โยธา | site, docs |
| `f-dynamics` | พลศาสตร์และการสั่นสะเทือน | การเคลื่อนที่, ความถี่ธรรมชาติ, ความไม่สมดุล, การวัดการสั่นของเครื่องจักร | factory, rail |

**ลำดับทำ**: ทำวิชาที่สายงานถัดไปต้องใช้ก่อนสายนั้นเสมอ เช่น สาย `plan` ต้องมี `f-units`, `f-reliability`, `f-econ` ก่อน · 1 PR = 2–3 วิชา · วิชาไฟฟ้าใช้เนื้อหาหมวด `elec-maint` ที่มีอยู่เป็นฐาน ไม่เขียนซ้ำ

**13 สาขาเดิม** ยังคงไว้ ภาพรวมกับข้อสอบ 4 ข้อห้ามแก้ (คีย์ทบทวน) · W6 เพิ่ม "จบสาขานี้ทำงานอะไรได้" และลิงก์ไปวิชาพื้นฐานที่สาขานั้นใช้ · E5 (ทฤษฎีรายสาขา) **ยกเลิก** เพราะวิชาพื้นฐานกลางครอบคลุมโดยไม่ซ้ำกันใน 13 สาขา ยกเว้นทฤษฎีเฉพาะสาขาที่วิชากลางไม่ครอบคลุม (เช่น อากาศพลศาสตร์ ปิโตรเลียม) ให้เพิ่มเป็นวิชา `f-…` ใหม่เมื่อเจ้าของต้องการ

## W1 · โครงหมวด "วิชาพื้นฐาน" + "สายงาน" (ROADMAP แถว 48)

**ขอบเขต**
- `course-data` เพิ่มคีย์ใหม่ `foundation` (วิชาพื้นฐาน — ดูหัวข้อ T) และ `career` (อาร์เรย์หัวข้อ) และ `classroom-engineering.jsx` เพิ่มหมวดใน `SUBJECTS` ชื่อ "สายงาน" / "Career tracks" · **id ของหมวดและหัวข้อเป็นส่วนหนึ่งของคีย์การ์ดทบทวน ตั้งแล้วห้ามเปลี่ยน**
- สายงาน 1 สาย = หัวข้อหลายหัวข้อ เพิ่มฟิลด์ `track` (id ของสายงาน) ให้หน้าเว็บจัดกลุ่มหัวข้อเป็นสายได้ เช่น `mnt-...` ทั้งชุด
- ฟิลด์ใหม่ของหัวข้อ `pre: [id]` (ต้องรู้ก่อน — id ข้ามหมวดได้ รูปแบบ `<หมวด>:<หัวข้อ>`) และ "ใช้ในงาน" ที่หน้าเว็บสร้างจาก `pre` เอง · เทสต์: ทุก id ใน `pre` มีอยู่จริง
- ฟิลด์ใหม่ใน quiz `why` (ไม่บังคับ, ข้อความสั้น) แสดงหลังตอบไม่ว่าจะถูกหรือผิด · ใช้ได้กับทุกหมวด รวมทั้ง `elec-maint` ที่จะเติมเหตุผลทีหลัง (ไม่เปลี่ยนลำดับข้อ) · `review.js` ฝั่งหลังการ์ดแสดง `why` ต่อจากคำตอบ

## E1 · ค่าอ้างอิงอิสระของสูตรไฟฟ้า (ROADMAP แถว 41)

**เป้าหมาย**: ให้ลัดวงจร แรงดันตก และขนาดกระแสใน `electrical-calc.js` มีตัวเลขจากเครื่องมืออิสระมาเทียบ ไม่ใช่ตัวเลขที่เขียนพร้อมกับสูตร

- `tools/eng-ref/` (ใหม่, ไม่รันใน CI): `gen_elec.py` สร้างกรณีด้วย pandapower (`pandapower.shortcircuit.calc_sc`, IEC 60909) และใช้ pandapower ที่ล็อกรุ่นไว้ใน `requirements.txt` · `README.md` บอกวิธีรันใน Colab หรือ sandbox (pypi เข้าได้)

- `tests/fixtures/elec-ref.json` (เขียนจากสคริปต์ครั้งเดียวแล้ว commit) มี `{gen: {tool, version, date}, cases: [{input, expect, tol}]}` · **ห้ามแก้มือ** ให้ถือแบบเดียวกับ `fsrs-original.js` คือแก้ได้ด้วยการรันสคริปต์ใหม่เท่านั้น
- `tests/electrical.spec.js`: ลูปเทียบ fixture กับ `ElecCalc` ภายใน `tol`

## E2 · แท็บรีเลย์ป้องกัน / เส้นโค้ง TCC (ROADMAP แถว 42)

**เป้าหมาย**: แท็บที่ 7 ใน `electrical.html` ใส่รีเลย์ 2–4 ตัว แล้วเห็นเส้นโค้งเวลา-กระแสบนกราฟ log-log พร้อมระยะห่างเวลา (grading margin) ที่กระแสลัดวงจร

**สูตร** (ใน `electrical-calc.js` · ส่วนใหม่ `relay*`)
- IEC 60255-151: `t = TMS · k / ((I/Is)^α − 1)` · SI (0.14, 0.02) · VI (13.5, 1) · EI (80, 2) · LTI (120, 1)
- IEEE C37.112: `t = TD · (A / (M^p − 1) + B)` · MI (0.0515, 0.02, 0.114) · VI (19.61, 2, 0.491) · EI (28.2, 2, 0.1217)
- ขั้น definite time และ instantaneous (I>>, I>>>) · ใช้ช่วง M ตั้งแต่ 1.1 ถึง 20 (ต่ำกว่า 1.1 ให้ถือว่าไม่ทำงาน)
- `relayCoord(relays, Ik)` คืนเวลาของแต่ละตัวที่ Ik และ margin ระหว่างคู่ที่ติดกัน เทียบเกณฑ์ 0.3 วินาที (รีเลย์ดิจิทัล) หรือ 0.4 วินาที (แบบจานหมุน) ซึ่งเป็นตัวเลือก · ค่าเกณฑ์ต้องอ้างที่มาในคอมเมนต์ (IEEE 242 / Buff Book)
- **known-answer**: ตัวอย่างมือจากสูตร (SI, TMS 0.1, M=10 → 0.297 วินาที) + เทียบกับเส้นโค้ง IEC ใน pandapower (`pandapower.protection`) ผ่าน fixture แบบ E1

## E3 · แท็บวิเคราะห์ก๊าซในน้ำมันหม้อแปลง DGA (ROADMAP แถว 43)

**เป้าหมาย**: กรอก ppm ของก๊าซ 5–7 ตัว (H2, CH4, C2H6, C2H4, C2H2 และ CO/CO2 ถ้ามี) แล้วได้ชนิดความผิดปกติจาก 3 วิธี พร้อมสามเหลี่ยม Duval

- อัตราส่วน IEC 60599 (C2H2/C2H4, CH4/H2, C2H4/C2H6) และ Rogers ratio
- เกณฑ์ค่าปกติ (typical values) ตามที่เจ้าของเลือก (IEC 60599 ตาราง A.1 หรือ IEEE C57.104-2019) · **ตัวเลขต้องให้เจ้าของตรวจ** และถ้าไม่มีที่มาให้ปล่อยว่าง ห้ามเดา
- known-answer: ตัวอย่างจาก IEC 60599 / บทความของ Duval + จุดบนขอบโซน (กันการปัดผิดฝั่ง) + กรณีก๊าซรวมเป็น 0 (ต้องไม่หารศูนย์)
- `duvals_triangle_plotter` (MIT) ใช้เป็นแหล่งอ้างอิงขอบโซนเท่านั้น ถ้าคัดลอกพิกัดมาต้องใส่การ์ดใน `credits.html`

**UI**: ฟอร์ม ppm · สามเหลี่ยม SVG แสดงโซนด้วยสี `--ome-chart-1..7` (7 โซนไม่เกิน 8 สี) และจุดของผลวัด · ตารางผลของ 3 วิธีวางคู่กัน · ลิงก์กลับไปบทเรียน `transformer` · `eng-audit` state `dga`

**โมเดล** Opus 5.5 · **effort** high · **skill** `tanot-design`, `test-driven-development`, `dataviz` · 🔍 ให้ session รีวิวตรวจตารางโซน

## E4 · แนวโน้มค่าที่วัดใน maintenance + ΔT เทอร์โมกราฟี (ROADMAP แถว 44)

**เป้าหมาย**: รายการตรวจชนิด `num` (เช่น กระแสมอเตอร์ ค่า IR อุณหภูมิขั้วต่อ) แสดงเป็นกราฟตามรอบของสินทรัพย์นั้น และเตือนเมื่อค่าเกิน `min/max` หรือค่อยๆ เคลื่อนไปทางขีดจำกัด

**ตรรกะ** (`mnt-calc.js`, ห้ามมีสูตรในหน้า)
- `readings(insps, assetId, itemId)` อ่านจากใบตรวจทุกปีที่มี ได้แก่ `tanot-mnt-<ปี>` ปีปัจจุบัน ±1 (ปีที่เก่ากว่านั้นถูกล็อก แต่ยังอ่านได้ผ่าน `TanotData.readIdb`) แล้วรวมเป็น `[{period, value, dev}]` เรียงตามรอบ · ถ้าสองเครื่องตรวจรอบเดียวกัน ให้ใช้ใบที่บันทึกหลังสุด (เวลาเขียนไว้ในใบ)
- `trend(points, {min, max})` คืน slope เชิงเส้นต่อรอบ, ค่าล่าสุด, `status` (`ok`/`warn`/`err`) และ `etaPeriods` (จะชนขีดในอีกกี่รอบเมื่อ slope ชี้ไปหาขีด และมีอย่างน้อย 4 จุด)
- `thermalSeverity(dT, basis)` แบ่งระดับตาราง NETA MTS 100.18: เทียบชิ้นส่วนเดียวกัน 1–3 / 4–15 / >15 °C · เทียบอุณหภูมิแวดล้อม 1–10 / 11–20 / 21–40 / >40 °C · **ต้องตรวจกับฉบับที่เจ้าของมี** เพราะฉบับต่างปีกันอาจใช้ตัวเลขไม่ตรงกัน
- known-answer ใน `tests/maintenance.spec.js`: ข้อมูล 2 เครื่อง × 3 ปี ข้ามขอบปีของฐานข้อมูล, รอบที่หายไป, ค่าที่ไม่ใช่ตัวเลข

**UI**: กล่องของสินทรัพย์ (`#asset=<id>`) เพิ่มส่วน "ค่าที่วัด" ซึ่งเป็น sparkline ต่อรายการ ใช้ `.list-row` ปุ่มเดียวขยายเป็นกราฟเต็ม (สีจาก `chart-theme.js`) · สินทรัพย์ที่ไม่มีรายการ `num` ไม่แสดงส่วนนี้ · ช่อง ΔT แบบไม่บังคับในฟอร์มตรวจเมื่อรายการมี `unit: '°C'`
- ห้ามเปลี่ยน schema IDB จึงไม่ต้อง bump version · ไม่มีคีย์ใหม่ · ถ้า "ต้องทำวันนี้" ของหน้าแรกจะรวม warn/err ของแนวโน้มด้วย ต้องแก้ `home-calc.js` แยกเป็นข้อย่อย (เสนอให้ทำทีหลัง)
- `eng-audit` state `mnt-trend` · ซิงก์ 2 context

**โมเดล** Sonnet 5.5 · **effort** high · **skill** `tanot-design`, `test-driven-development`, `dataviz`, `break-ui` · แหล่ง: `docs/maintenance-design.md` + CLAUDE.md "Maintenance log"
